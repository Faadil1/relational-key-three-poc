# ROUND 12B.3 — REGISTERED CITY PASSAGE VISUAL GRAMMAR

Status: FROZEN FOR PROTOTYPING
Project: RELATIONAL KEY — Cultural Editions
Pilot: 01 / STO Youth Civic Mobility

## 1. Purpose

Translate the promoted STO-derived mechanism into a repeatable visual grammar without copying the STO Multi Jeunesse artwork or its unresolved iconography.

Canonical direction:

> REGISTERED CITY PASSAGE
>
> A young person's right to move through the city becomes visible only when the civic relationship is registered.

This is not a STO redesign. It is a RELATIONAL KEY Cultural Edition whose mechanism is grounded in documented youth-transit behaviors: shared civic object, personal ownership, repeated validation, multi-year continuity, and a network-bounded right to move.

---

## 2. Invariants — must remain recognizably RELATIONAL KEY

Every territory variant must preserve:

1. CR80 credential proportions (85.60 × 53.98 mm target).
2. Registered Continuation as the primary law.
3. One interrupted path before registration.
4. One registration junction as the dominant proof event.
5. The exact same path continues after a valid relationship.
6. No Match must indicate relational incompatibility, not invalid identity.
7. The card remains a functional credential: identity, entitlement context, ID/fallback verification and validity remain legible.
8. Explanation is on demand, not printed as a benefits inventory on the front.
9. Territory information never obstructs QR/barcode/NFC/ID safe zones.
10. The cultural layer must survive a monochrome geometry test.

If logos, colors, names and illustrations are removed, the card should still read as a RELATIONAL KEY object.

---

## 3. Variable layer — what a territory may change

A territory may change only evidence-backed layers:

- local-field geometry
- path rhythm before/after the junction
- node density and spacing
- street/corridor labels
- coordinate marks / sector abbreviations
- secondary palette
- micro-pattern density
- route-family notation
- collectible numbering
- motion cadence during registration

A territory may NOT change:

- core junction logic
- semantic meaning of the path
- valid/no-match causal model
- explanation hierarchy
- credential manufacturability

Rule:

> TERRITORY CHANGES THE FIELD, NOT THE PRODUCT LAW.

---

## 4. Front-face architecture

Reference frame: 856 × 540 px design canvas.

### Zone A — Credential identity
Approx. top-left 18–22% of surface.

Contains:
- RELATIONAL KEY series mark
- edition / territory name
- member tier or youth credential type

Must remain quieter than the relational geometry.

### Zone B — Registered City Field
Approx. 50–65% visual impact.

Contains:
- fragmented local field
- selected street/corridor fragments
- civic nodes / transfer marks
- interrupted path
- registration junction

The field must not look like a literal Google/transport map. It is a compressed civic notation system.

### Zone C — Functional identity
Lower / edge-safe zone.

Contains:
- member name or writable personal trace
- credential ID
- validity
- optional five-year progression index
- subtle NFC marker

### Zone D — Registration edge
The path must approach one physical edge of the credential so it can visually continue into a destination / validator / paired surface.

This edge relationship is mandatory.

## 5. Back-face architecture

Back = STRATA / provenance / functional verification.

Required bands:

1. HOLDER
   - name / writable field
   - optional member ID

2. ISSUER / EDITION
   - issuer type
   - territory edition
   - series number

3. VALIDITY
   - valid through
   - entitlement scope

4. NETWORK CLAIM
   - accepted relation / youth mobility claim

5. FALLBACK
   - QR / barcode / manual verification

6. ARCHIVE TRACE
   - a tiny series notation identifying the source-mechanism family, not the copied source image
   - e.g. `YOUTH CIVIC MOBILITY / VALIDATION / LOCAL FIELD`

The back must feel like an institutional object, not a poster.

---

## 6. Local-field construction grammar

The local field is built from four primitive families.

### F1 — Corridor fragments
Short linear pieces derived from documented local street/corridor names.
- never render a full map
- 3–7 fragments maximum on front
- mixed lengths
- no decorative random lines

### F2 — Civic nodes
Small marks for stations, transfer points, service points or district anchors.
- circles, ticks or registered dots
- maximum 5 dominant nodes
- hierarchy by size, not by pictogram library

### F3 — Sector labels
Microtypographic place labels.
Examples may include sector names or verified street/corridor names.
- uppercase condensed or mono
- never more than 3 dominant labels
- secondary labels at 40–60% visual weight

### F4 — Registration path
The only line with semantic continuity.
- stronger than the field
- crosses or threads through local fragments
- stops at the junction before registration
- continues unchanged after registration

The viewer should understand that the field represents the city, while the stronger path represents the member's possible passage through it.

---

## 7. Junction grammar

The junction remains the signature.

Before:

`━━━━━━◐       ◑━━━━━━`

Registered:

`━━━━━━●━━━━━━━━━━━━`

No Match:

`━━━━━━◐       ◒━━━━━━`

For the Youth Civic Mobility edition, the junction also means:

- valid credential interaction
- real passage recorded even when fare = 0
- transition from potential mobility to registered mobility

No currency icon. No ticket-checkmark icon. No giant NFC ring.

---

## 8. Microtypography rules

Primary labels:
- territory / edition: 18–26 px @ 856×540
- member tier / youth type: 30–52 px

Field labels:
- dominant local label: 13–17 px
- secondary corridor labels: 9–12 px
- tracking: +2% to +8%
- uppercase preferred for civic notation

Metadata:
- 8–11 px
- mono or neutral grotesk

Rules:
- place names must come from verified sources
- no invented neighborhood names
- no slogans presented as historical facts
- abbreviations must be documented or transparently system-generated

---

## 9. Palette grammar

Canonical RELATIONAL KEY colors remain available:
- cobalt / ultramarine = credential / member
- signal vermilion / orange = registration event
- warm ivory = institutional field
- charcoal = structure

Territory variants may add ONE secondary family only after evidence review.

The secondary family must come from:
- archive object palette
- local civic signage / printed ephemera
- documented institutional material

It must NOT come from:
- flag-color shortcuts
- generic national palettes
- tourism branding assumptions

Pilot 01 prototypes will initially stay mostly canonical to isolate geometry before local color variation.

---

## 10. Five-Year Spine — optional supporting layer

The STO youth program's multi-year companion behavior can appear as a subtle progression structure.

Permitted implementations:
- five micro-ticks
- five registration notches
- five quiet strata bands

Not permitted:
- gamified progress bar
- badges / streaks
- fake usage history

This layer is secondary and must never compete with the main junction.

---

## 11. Personal trace — optional supporting layer

Because the youth card can be a shared civic object personalized by the holder, a writable or owner-mark field is permitted.

Preferred:
- handwritten-name zone
- small owner trace
- non-biometric personalization

Avoid:
- mandatory portrait as the visual thesis
- avatar systems
- decorative signatures presented as real signatures

---

## 12. First three STO territory prototypes

These are deliberately selected to test three different spatial regimes, not to claim three cultural identities.

### P01 — HULL / CIVIC GRID

Evidence basis:
- STO network explicitly serves Hull.
- Current network map includes a dedicated Centre-ville Hull inset.

Geometry thesis:
- compressed urban grid
- short overlapping civic fragments
- high node density
- path must negotiate a dense field before registration

Visual behavior:
- compact labels
- tighter spacing
- junction sits near a dense crossing

What it tests:
- whether Registered City Passage works in a dense civic environment.

### P02 — GATINEAU / LINEAR CORRIDOR

Evidence basis:
- STO network explicitly serves Gatineau.
- Rapibus is a major network structure and the official service infrastructure includes Rapibus stations.
- Station de la Cité is a current STO service point in the Gatineau sector.

Geometry thesis:
- longer directional spine
- fewer but stronger perpendicular branches
- registration feels like joining a civic corridor

Visual behavior:
- more horizontal rhythm
- larger spacing between nodes
- continuation path can align with the corridor after registration

What it tests:
- whether the system can feel directional rather than grid-like.

### P03 — BUCKINGHAM + MASSON-ANGERS / EASTERN PAIR

Evidence basis:
- STO officially groups Buckingham and Masson-Angers in network/service contexts.
- Current STO map contains a Buckingham / Masson-Angers inset.
- STO currently offers on-demand service in these sectors to connect to the regular network via Station Lorrain.

Geometry thesis:
- two sparse local fields
- a bridging relation into one regular-network node
- the junction becomes a connector between distributed local access and the main network

Visual behavior:
- larger negative space
- paired node clusters
- registration creates the visible bridge

What it tests:
- whether RELATIONAL KEY can represent distributed / demand-responsive access without becoming a literal route map.

## 13. Prototype acceptance tests

Each of the three prototypes must pass:

1. Logo-off test — still recognizable as RELATIONAL KEY.
2. Color-off test — territory logic remains legible in geometry.
3. 5-second test — viewer sees card + city field + interrupted relationship.
4. Match test — registration visibly completes a passage.
5. No-match test — path does not continue, but card remains valid.
6. Territory differentiation test — Hull / Gatineau / Eastern Pair are distinguishable without changing the core product law.
7. Map-avoidance test — no prototype looks like a mini transit map.
8. Archive honesty test — every place label / field claim is source-verifiable.
9. Manufacturability test — no hero geometry depends on impossible holographic / emissive effects.
10. Series test — all three look like one collection.

---
